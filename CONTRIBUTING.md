# Как предложить правку

Нашли ошибку, неточность или место, которое трудно понять? Его можно исправить самому через
pull request (PR). Заодно это способ попробовать на практике обычный командный процесс: ветка, PR,
автоматические проверки, review.

## Что можно предложить

- фактические ошибки, опечатки, неточные формулировки;
- неработающие или устаревшие примеры кода;
- более понятное объяснение: другую формулировку, пример, диаграмму, таблицу;
- недостающие варианты примеров на других языках из переключателя (Kotlin, C#, Java, Go);
- полезные ссылки в раздел «Дополнительное чтение».

Не стоит присылать перестановку слов без улучшения смысла, массовое переформатирование и правки
кода сайта вместе с правкой лекции: это отдельный PR. Если хотите переписать большой раздел или
добавить новый, сначала откройте issue и опишите идею, чтобы не делать работу зря.

Если используете нейросеть, проверьте результат сами: за содержание PR отвечает его автор.

## Где лежит текст

| Страница на сайте | Файл в репозитории                   |
| ----------------- | ------------------------------------ |
| `/lectures/03`    | `content/lectures/Lec3/vitepress.md` |
| `/intro`          | `content/intro/vitepress.md`         |
| `/conclusion`     | `content/conclusion/vitepress.md`    |
| `/extras/02`      | `content/extras/02/vitepress.md`     |
| Картинки лекции   | `content/lectures/LecN/assets/`      |

Номер лекции в адресе всегда двузначный: `/lectures/03` собирается из папки `Lec3`.

## Как сделать PR

Нужны Git и Node 24 или новее.

```sh
# 1. Сделайте fork репозитория кнопкой Fork на GitHub, затем:
git clone https://github.com/<ваш-логин>/KPO.git
cd KPO
git switch -c fix/lec3-di-example

# 2. Запустите сайт локально и правьте файлы: страница обновляется сама
npm ci
npm run dev

# 3. Перед отправкой проверьте контент и сборку
npm run content:check
npm run build

# 4. Отправьте ветку в свой fork и откройте PR на GitHub
git add content/lectures/Lec3/vitepress.md
git commit -m "Лекция 3: исправлен пример с DI"
git push -u origin fix/lec3-di-example
```

После `git push` GitHub покажет ссылку на создание PR, или откройте свой fork и нажмите
**Compare & pull request**.

## Как оформить PR

- Один PR, одна тема: одна ошибка или одно пояснение. Маленькие PR быстрее проверяются.
- Заголовок говорит, что изменилось: «Лекция 3: исправлен пример с DI».
- В описании коротко объясните, что было не так и почему стало лучше. Для фактической ошибки дайте
  ссылку на источник.

Как выглядят примеры на нескольких языках, Playground, диаграммы и другие блоки, видно на странице
[`/intro`](https://kert0n.github.io/KPO/intro). Проще всего скопировать разметку из её исходника
`content/intro/vitepress.md`. Шпаргалка и неочевидные правила собраны в
[`docs/authoring.md`](docs/authoring.md).

## Что будет после открытия PR

1. **Автоматические проверки.** GitHub Actions проверит ссылки, разметку, запускаемые
   Kotlin-примеры и сборку. У первого PR из fork проверки стартуют после того, как мейнтейнер их
   одобрит. Если что-то упало, откройте **Details** у красной проверки, исправьте и сделайте
   `git push` в ту же ветку: PR обновится сам, новый открывать не нужно.
2. **AI-ревью CodeRabbit.** Автоматически он не запускается: если PR меняет смысл (объяснение,
   пример кода, новый раздел, код сайта), напишите в PR комментарий `@coderabbitai review`.
   Подробнее в разделе [CodeRabbit](#coderabbit) ниже.
3. **Review.** PR посмотрит преподаватель, семинарист или ассистент. Если попросят что-то изменить,
   отвечайте в комментариях и пушьте исправления в ту же ветку.
4. **Merge.** После слияния сайт и PDF курса обновятся автоматически через несколько минут.

## CodeRabbit

[CodeRabbit](https://coderabbit.ai) — AI-ревьюер, который оставляет замечания прямо в PR. Квота
ревью у репозитория маленькая и общая на всех, а само ревью идёт несколько минут, поэтому
вызывайте его только для смысловых PR.

| Вызывать                            | Не вызывать                                           |
| ----------------------------------- | ----------------------------------------------------- |
| новое или переписанное объяснение   | опечатки, пунктуация, форматирование                  |
| новый или исправленный пример кода  | обновление зависимостей (Dependabot пропускается сам) |
| новый раздел, лекция или дополнение | правка ссылки или картинки                            |
| изменения кода сайта, скриптов, CI  |                                                       |

Как пользоваться:

- Вызов — комментарий `@coderabbitai review` в PR. Повторный вызов после новых коммитов проверяет
  только изменения с прошлого ревью.
- За один вызов CodeRabbit проверяет меньше 100 файлов, изменённых с прошлого ревью. Если PR
  больше, пушьте его порциями: например, 150 файлов — двумя пушами по 75, вызывая ревью после
  каждого.
- Замечания CodeRabbit — подсказки, а не приказ. Исправьте то, с чем согласны, на остальное
  ответьте в треде, почему оставили как есть. Окончательное решение остаётся за человеком на
  review.

## Баллы

> Правила начисления баллов за принятые PR определяет преподаватель курса. Они будут добавлены
> сюда.
