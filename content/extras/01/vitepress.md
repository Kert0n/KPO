# Песочница

В условиях акции написано «скидка при заказе от 10 000 ₽». Покупатель набрал товаров ровно на 10 000 ₽. Получит ли он скидку? На таком заказе удобно проверить, точно ли код передаёт смысл слова «от».

Сюда можно переносить короткие фрагменты из лекций, менять одно правило и смотреть, у кого изменится результат. У нашей акции есть ещё одно условие. Клиент со статусом `pro` получает скидку при любой сумме заказа. Для эксперимента достаточно двух полей — суммы в целых рублях и статуса (`basic` или `pro`). Функция `hasDiscount` возвращает `true`, если скидка положена.

## Кому положена скидка? {#runnable-kotlin-playground}

Представьте, что вы проверили два заказа обычного клиента (`basic`) на 7 500 и на 12 000 ₽. Один слишком мал для скидки, другой подходит. Если случайно написать `>` вместо `>=`, оба ответа по-прежнему будут верными. Какой заказ обнаружит ошибку?

В блоке ниже выберите **Kotlin**. Если редактор ещё закрыт, нажмите **Playground**. В `main` найдите список заказов. Предскажите результат для каждой строки, затем запустите программу кнопкой ▶. В соседних вкладках то же правило записано на C#, Java и Go.

::: multi-code "Проверка правила скидки"

```kotlin
data class Order(val total: Int, val customerTier: String)

fun hasDiscount(order: Order): Boolean {
    return order.total >= 10_000 || order.customerTier == "pro"
}
```

```kotlin playground
data class Order(val total: Int, val customerTier: String)

fun hasDiscount(order: Order): Boolean {
    return order.total >= 10_000 || order.customerTier == "pro"
}

fun main() {
    val orders = listOf(
        Order(total = 9_999, customerTier = "basic"),
        Order(total = 10_000, customerTier = "basic"),
        Order(total = 12_000, customerTier = "basic"),
        Order(total = 9_999, customerTier = "pro"),
        Order(total = 10_000, customerTier = "pro")
    )

    for (order in orders) {
        println("${order.total} ${order.customerTier} -> ${hasDiscount(order)}")
    }
}
```

```csharp

public static class Discounts
{
    public static bool HasDiscount(Order order)
    {
        return order.Total >= 10_000 || order.CustomerTier == "pro";

```

```java
record Order(int total, String customerTier) {}

class Discounts {
    static boolean hasDiscount(Order order) {
        return order.total() >= 10_000 || "pro".equals(order.customerTier());
    }
}
```

```go
type Order struct {
    Total        int
    CustomerTier string
}

func HasDiscount(order Order) bool {
    return order.Total >= 10_000 || order.CustomerTier == "pro"
}
```

:::

Теперь замените в `hasDiscount` только `>=` на `>`. Снова запустите программу на тех же заказах. У двух покупателей в списке сумма ровно 10 000 ₽. У скольких из них изменился ответ?

::: details Сверить оба запуска

| Сумма, ₽ | Статус | Исходное `>=` | После замены на `>` |
| -------: | ------ | ------------- | ------------------- |
|    9 999 | basic  | false         | false               |
|   10 000 | basic  | true          | false               |
|   12 000 | basic  | true          | true                |
|    9 999 | pro    | true          | true                |
|   10 000 | pro    | true          | true                |

Скидку потерял только клиент `basic` с заказом на 10 000 ₽. У клиента `pro` на ту же сумму тоже перестало выполняться условие по сумме, но скидку даёт статус. Оператор `||` означает «или». Для скидки достаточно хотя бы одного выполненного условия. Чтобы проверить сам порог, берите заказ клиента `basic`, для которого второе условие ложно.
:::

## Практика

Магазин меняет условия акции. Теперь скидка положена только клиентам `pro` при заказе **от** 10 000 ₽. Верните знак `>=`. Какой оператор между двумя условиями передаёт новое правило? Измените его и запустите те же пять заказов.

::: details Проверить новое правило

Нужен оператор `&&` («и»). Скидку получит только последний покупатель, `pro` с заказом на 10 000 ₽. Заказ `basic` на 12 000 ₽ проверяет, что одной суммы теперь мало. Заказ `pro` на 9 999 ₽ проверяет, что одного статуса тоже мало.
:::

## Шаблон для эксперимента

1. Возьмите из Kotlin-примера в лекции одну функцию и типы, которые ей нужны. В редакторе Kotlin замените ими пример со скидкой, а в `main` выведите результат вызова функции.
2. Подберите вход, на котором два варианта правила дадут разные ответы, и ещё один, на котором они совпадут. Запишите прогноз.
3. Запустите исходный код, внесите одну правку и повторите запуск на тех же данных.
4. Сравните вывод с прогнозом. Если результат отличается от ожидаемого, укажите конкретный вход и условие, которое дало неожиданный ответ.

::: warning Важно
Оставьте в редакторе только то, что нужно для проверки одного правила. Если функция читает базу или файл, для первого опыта передайте ей готовые данные.
:::

Такие пары «вход — ожидаемый ответ» можно сохранить как примеры для автоматической проверки. В [лекции 3](/lectures/03#параметризованные-тесты) показано, как один параметризованный тест прогоняет несколько наборов данных.
